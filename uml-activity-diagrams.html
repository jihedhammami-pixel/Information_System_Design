What is an activity diagram?

A picture of a process, step by step

An activity diagram shows the actions of a process and the order in which they happen. It shows where the flow chooses between paths, where it repeats, and which steps run in parallel. It is one of the UML behavior diagrams.

Business processes

How a shop handles an order, how a library lends a book.

Use case scenarios

The detailed flow behind one use case, such as "Withdraw cash".

Algorithms

The logic of a method: loops, conditions, and steps.

How to read one: follow the token. Imagine a small token that starts at the initial node and travels along the arrows. Each action it reaches is executed. At a decision it takes one path. At a fork it splits into several tokens. When it reaches the final node, the activity is over. The simulators in this chapter work exactly like this.

Decisions, merges and loops

Choosing one path, and coming back

A decision diamond has one flow in and several flows out. Each outgoing flow carries a guard, a condition in square brackets such as [valid]. The token takes the one branch whose guard is true. A merge diamond does the opposite: several flows in, one flow out. Pointing a flow back up to a merge creates a loop.

Guards must not overlap

[age ≥ 18] and [age < 18], never [age ≥ 18] and [age ≥ 16].

Guards must cover every case

Use [else] for "everything else", so the token never gets stuck.

A merge does not wait

Each token that arrives passes straight through. Only a join waits.

    Parallel flows: fork and join

    Doing several things at the same time

    A fork is a thick bar with one flow in and several flows out. It turns one token into one token per branch, and all branches run concurrently. A join is a bar with several flows in and one out. It waits until a token has arrived from every branch, then lets one token continue.

      Activity final ◉

      Ends the whole activity at once. Every other token is destroyed.

      Flow final ⊗

      Ends only the token that reaches it. Other branches keep running.

      Parallel ≠ simultaneous

      "Parallel" means the order between branches doesn't matter. They may really run at the same time, or one after the other.

      5

      Swimlanes: who does what?

      Partitions split the diagram by actor, role or system

      A swimlane (UML calls it an activity partition) is a column, or a row, labelled with a person, role, department or system. Every action is placed in the lane of whoever performs it. When a flow crosses a lane border, the responsibility passes to someone else.

        From text to diagram in 5 steps

        The method you'll use in every exercise and exam

        Read the scenario and mark its words by kind. Each kind of word becomes a kind of symbol. Click the steps to build the diagram.

        A member comes to the desk to borrow a book (start). The librarian scans the member card. If the card is expired, the librarian asks the member to renew it and the loan stops. Otherwise, the librarian scans the book. Then, at the same time, the system records the loan and prints a receipt. When both are done, the librarian hands over the book and the loan is complete.

        • Start and end → initial / final nodes
        • Verbs → actions
        • if / otherwise → decision + guards
        • at the same time → fork / join

        Golden rules

        The mistakes teachers see most often, and how to avoid them

        Name actions with a verb

        An action is a step of work.✗ Database✓ Query the database

        Put guards on every decision

        Otherwise nobody knows which way to go.✗ two unlabelled arrows✓ [paid] / [not paid]

        Cover every case

        Leave no gap between guards.✗ [t > 30] / [t < 30]✓ [t > 30] / [else]

        Decision ↔ merge, fork ↔ join

        Close alternatives with a merge, parallel branches with a join.✗ decision … join✓ decision … merge

        Nothing leaves a final node

        The activity final ends everything.✗ ◉ → Send report✓ Send report → ◉

        Keep one direction

        Draw top to bottom (or left to right). Only loops go back up.✗ arrows in every direction✓ a clear vertical spine
