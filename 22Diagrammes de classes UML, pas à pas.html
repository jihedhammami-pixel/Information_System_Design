    Idée clé

    Qu’est-ce qu’un diagramme de classes ?

    Un diagramme de classes est une image de la structure d’un système logiciel. Il montre quels types d’éléments existent, ce que chacun sait, ce que chacun sait faire et comment ils sont reliés. Il ne montre ni le temps ni l’ordre des événements : cela relève d’autres diagrammes UML, comme les diagrammes de séquence.

    Idée 1.1 · Classe ou objet

    Une classe est un modèle. Les objets sont fabriqués à partir d’elle.

    • Une classe décrit un type d’élément : Student (étudiant), Car (voiture), Cookie (biscuit).
    • Un objet (ou instance) est un élément concret fabriqué à partir de cette classe, avec ses propres valeurs.
    • Une classe peut produire autant d’objets que nécessaire. Ils ont la même forme mais contiennent des données différentes.
    • UML écrit un objet sous la forme nom : Classe, souligné.
    Analogie · L’emporte-pièce

    L’emporte-pièce est la classe : il décide de la forme. Chaque biscuit découpé est un objet. Chaque biscuit peut avoir son propre parfum et sa propre taille, mais tous viennent du même emporte-pièce.

    Le plan d’un architecte fonctionne de la même façon : un seul plan, de nombreuses maisons réelles.

    Simulation

    L’usine à objets

    moule

    1 classe → 0 objet

    Remarquez : chaque objet possède les deux mêmes attributs, car c’est la classe qui les définit. Seules les valeurs changent.

    Idée clé

    Les trois compartiments d’une classe

    Chaque classe est dessinée comme un rectangle divisé en trois parties, de haut en bas : son nom, ses attributs (ce qu’elle sait) et ses opérations (ce qu’elle sait faire). Cliquez sur chaque partie de la boîte pour l’explorer.

    Idée 2.1 · Nom, attributs, opérations
    BankAccount
    - owner : String
    - balance : double
    - iban : String
    + deposit(amount : double) : void
    + withdraw(amount : double) : boolean
    + getBalance() : double
    Idée 2.2 · Des mots à la classe

    Comment trouver les classes, les attributs et les opérations

    • Les noms d’une description deviennent souvent des classes : « Un étudiant s’inscrit à un cours. »
    • Les propriétés d’un nom deviennent des attributs : le nom et le numéro d’un étudiant.
    • Les verbes deviennent des opérations : s’inscrire, payer, imprimer.
    • Les noms de classe sont au singulier et commencent par une majuscule : Student, pas students.
    Analogie · Une carte d’identité

    Voyez une classe comme le modèle d’une carte d’identité. Le titre indique le type de carte. Le milieu liste les informations imprimées (nom, date de naissance). Le dos liste ce que le titulaire a le droit de faire (entrer à la bibliothèque, emprunter des livres).

      Idée clé
      
    
      Visibilité : qui peut voir quoi
      
    
      Le petit symbole devant chaque attribut ou opération indique quelles autres classes ont le droit de l’utiliser. Cacher l’intérieur d’une classe et n’offrir que quelques opérations publiques s’appelle l’encapsulation.
      

    
      
      Idée 3.1 · Quatre symboles
      
      
        
      +
      publicToute classe peut l’utiliser.
      
        
      -
      privéSeulement la classe elle-même.
      
        
      #
      protégéLa classe et ses sous-classes.
      
        
      ~
      paquetageLes classes du même paquetage.
      
      
      
    
      

    
      
      Idée 3.2 · L’analogie de la maison
      
      
        
      
          
      Analogie · Les pièces d’une maison
      
          
      Le salon est public : les invités y entrent. Votre chambre est privée : vous seul. La cuisine familiale est protégée : vous et vos enfants. La boîte aux lettres de la rue est de niveau paquetage : les voisins de votre rue peuvent l’atteindre.
      
        
      
        
      
          
      Règle simple pour débuter
      
          
        
            
      • Rendez les attributs - privés.
        • 
            
      • Rendez + publiques les opérations dont les autres classes ont besoin.
        • 
            
      • N’utilisez # que si une sous-classe a vraiment besoin du membre.
        • 
            
      • Les langages diffèrent sur les détails. En Java, par exemple, les membres protégés sont aussi visibles dans le paquetage.
        •

      Idée clé
      
    
      Écrire les attributs et les opérations
      
    
      UML a une petite grammaire pour chaque ligne d’une classe. Le type vient toujours après les deux-points, à l’inverse de Java ou de C. Apprenez ces deux modèles et vous pourrez lire presque n’importe quelle classe.
      

    
      
      Idée 4.1 · Deux modèles
      
      
        
      
          
      Attribut
      
          
      visibilité nom : Type [multiplicité] = défaut
      
          
      Opération
      
          
      visibilité nom(param : Type, …) : TypeRetour
      
          
        
            
      • Souligné signifie statique : le membre appartient à la classe et est partagé par tous les objets.
        • 
            
      • Italique signifie abstrait : déclaré ici, implémenté par les sous-classes.
        • 
            
      • Les parties entre crochets sont facultatives. Les débutants peuvent souvent les omettre.
        • 
          
      
        
      
        
      
          
      Analogie · Une étiquette de livraison
      
          
      Une ligne d’opération ressemble à une étiquette de livraison. Le symbole dit qui peut l’envoyer, le nom dit ce que c’est, les parenthèses listent ce que vous devez fournir, et la partie après les derniers deux-points dit ce que vous recevez en retour.

      uml / 05-associations-et-multipliciteFenêtre 5 sur 11
      
  
      
    05
    
      Idée clé
      
    
      Associations et multiplicité
      
    
      Une association est un trait plein entre deux classes. Elle signifie que leurs objets sont liés et se connaissent : un Teacher (enseignant) enseigne un Course (cours). Les nombres sur le trait, appelés multiplicité, indiquent combien d’objets peuvent être liés.
      

    
      
      Idée 5.1 · Lire les nombres
      
      
        
      1exactement un
      
        
      0..1zéro ou un
      
        
      *un nombre quelconque (0..*)
      
        
      1..*un ou plusieurs
      
        
      2..4entre deux et quatre
      
      
      
      
      
        
      
          
      Lisez le nombre à l’autre bout
      
          
      Dans Person 1 ── 0..1 Passport, partez de Person et suivez le trait. Le nombre placé à côté de Passport (0..1) indique combien de passeports une personne peut avoir. Dans l’autre sens : chaque passeport appartient à exactement 1 personne.
      
          
      Vous pouvez aussi ajouter un nom au trait (possède), des noms de rôle à chaque extrémité, et une flèche ouverte pour montrer quel côté peut naviguer vers l’autre.
      
        
      
        
      
          
      Analogie · Places et billets
      
          
      Un billet de concert donne exactement 1 place, et une place peut être vendue à 0..1 billet. La multiplicité est la règle affichée au guichet : si on l’enfreint, le système est dans un état invalide.
      
        
      
      
      

      
      
        
      Simulation
      Testeur de multiplicité
      Touchez un objet à gauche, puis un objet à droite pour les lier ou les délier. Faites passer toutes les boîtes au vert.
      
        
      
          
          
          
        
      
        
      
        
      
        
      
        
      
      
      
    
      

    
      
  
      

      



      
  
      uml / 06-agregation-ou-compositionFenêtre 6 sur 11
      
  
      
    06
    
      Idée clé
      
    
      Le tout et ses parties : agrégation ou composition
      
    
      Certaines associations signifient « est composé de » ou « possède ». UML ajoute un losange du côté du tout. La couleur du losange répond à une question : quand le tout est détruit, les parties disparaissent-elles aussi ?
      

    
      
      Idée 6.1 · Losange blanc ou noir
      
      
        
      
          
      Agrégation · Une équipe et ses joueurs
      
          
      Un losange blanc (vide) ◆ signifie un « possède » faible. Les parties peuvent exister seules et être partagées. Si une équipe est dissoute, les joueurs existent toujours et peuvent rejoindre une autre équipe.
      
        
      
        
      
          
      Composition · Une maison et ses pièces
      
          
      Un losange noir (plein) ◆ signifie un « est composé de » fort. Chaque partie appartient à un seul tout, et vit et meurt avec lui. Démolissez la maison et ses pièces disparaissent.
      
        
      
      
      

      
      
        
      Simulation
      Le test de démolition
      Supprimez le tout et observez ce qui arrive à ses parties.
      
        
      
          
      
            
      Agrégation ◆ Team possède des Players
      
            
      
            
      Trois objets joueur sont liés à un objet équipe.
      
            
          
      
          
      
            
      Composition ◆ House est composée de Rooms
      
            
      
            
      Trois objets pièce appartiennent à un objet maison.
      
            
          
      
        
      
        
      Astuce : le losange touche toujours le tout, jamais la partie.
      
      
      
    
      

    
      
  
      

      



      
  
      uml / 07-heritageFenêtre 7 sur 11
      
  
      
    07
    
      Idée clé
      
    
      L’héritage : la relation « est un »
      
    
      Quand une classe est un cas particulier d’une autre, UML dessine une généralisation : un trait plein avec un triangle vide pointant vers la classe générale (le parent, ou superclasse). L’enfant (sous-classe) reçoit automatiquement les attributs et les opérations du parent, et peut ajouter les siens ou changer le fonctionnement d’une opération (redéfinition).
      

    
      
      Idée 7.1 · Le test « est un » et les classes abstraites
      
      
        
      
          
        
            
      • Testez avec une phrase : « Un chien est un animal » sonne juste, donc l’héritage convient. « Une voiture est un moteur » sonne faux : c’est un « possède ».
        • 
            
      • Le triangle pointe toujours vers le parent.
        • 
            
      • Une classe abstraite s’écrit avec son nom en italique (ou avec {abstract}). On ne peut pas créer directement d’objets de cette classe.
        • 
            
      • Une opération en italique est abstraite : chaque sous-classe doit la fournir.
        • 
          
      
        
      
        
      
          
      Analogie · Le livre de recettes de famille
      
          
      Chaque enfant de la famille reçoit le livre de recettes de grand-mère (membres hérités). Chaque enfant peut ajouter de nouvelles recettes (membres propres) et réécrire une recette à sa façon (redéfinition). Cela reste un livre de recettes de famille : quiconque en demande une obtient une réponse valide.
      
        
      
      
      

      
      
        
      Simulation

      uml / 08-interfaces-et-dependanceFenêtre 8 sur 11
      
  
      
    08
    
      Idée clé
      
    
      Interfaces, réalisation et dépendance
      
    
      Une interface est un contrat : une liste d’opérations sans code derrière. Une classe qui promet de fournir ces opérations réalise (implémente) l’interface, ce qui se dessine par un trait pointillé avec un triangle vide. Une dépendance est le lien le plus faible : un trait pointillé avec une flèche ouverte, qui signifie « utilise un instant ».
      

    
      
      Idée 8.1 · L’interface comme contrat
      
      
        
      
          
      Analogie · Une prise murale
      
          
      La prise se moque de savoir si vous branchez un téléphone, un ordinateur portable ou une voiture électrique. Elle exige seulement que l’appareil ait la bonne fiche. La prise est l’interface ; chaque appareil muni de cette fiche la réalise.
      
        
      
        
      
          
        
            
      • Dessinez une interface comme une boîte de classe avec «interface» au-dessus du nom.
        • 
            
      • Elle ne contient généralement que des opérations.
        • 
            
      • Des classes sans lien entre elles peuvent réaliser la même interface.
        • 
          
      
        
      
      
      
      
      
        
      Simulation
      Branchez-le
      Touchez un appareil. Seules les classes qui réalisent Chargeable se rechargeront.
      
        
      
          
      
          
      
          
      
          
      
        
      
      
      
    
      

    
      
      Idée 8.2 · Dépendance : utiliser sans garder
      
      
        
      
          
      Si une classe ne fait qu’utiliser brièvement une autre classe (en paramètre, en variable locale ou en appelant une méthode statique) sans en garder de référence dans un attribut, c’est une dépendance. Un changement dans la classe utilisée peut casser celle qui l’utilise : c’est pourquoi on la dessine quand même.
      
        
      
        
      
          
      Analogie · Un couteau emprunté
      
          
      Un chef emprunte un couteau seulement le temps de cuisiner, puis le rend. Pas de relation durable, mais si le couteau était émoussé, la recette échouerait.
      
        
      
      
      
      
      
        
      Simulation
      La dépendance n’existe que pendant l’appel

    private final Engine engine = new Engine(); // créé à l’intérieur, jamais partagé
    private Driver driver;                  // fourni de l’extérieur, survit

    }

      Niveau 8
      Défi de conception : une appli musicale
      ★★★★★
      
        
      
          
      Un User (utilisateur) a exactement un Profile (profil), créé avec le compte et supprimé avec lui. Un utilisateur peut créer un nombre quelconque de Playlists. Une playlist contient des Songs (chansons) ; supprimer une playlist ne supprime pas ses chansons, et une chanson peut figurer dans plusieurs playlists.

La classe Player reçoit un Playable en paramètre pour le jouer, mais ne le stocke jamais.
