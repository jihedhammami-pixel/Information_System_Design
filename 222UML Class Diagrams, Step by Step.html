    Big idea

    What is a class diagram?

    A class diagram is a picture of the structure of a software system. It shows which kinds of things exist, what each one knows, what each one can do, and how they are connected. It does not show time or order of events. Those belong to other UML diagrams, such as sequence diagrams.

    Idea 1.1 · Class vs object

    A class is a template. Objects are made from it.

    • A class describes a kind of thing: Student, Car, Cookie.
    • An object (or instance) is one concrete thing made from that class, with its own values.
    • One class can produce as many objects as you need. They share the same shape but hold different data.
    • UML writes an object as name : Class, underlined.
    Analogy · The cookie cutter

    The cookie cutter is the class: it decides the shape. Every cookie you press out is an object. Each cookie can have its own flavor and size, but they all come from the same cutter.

    An architect's blueprint works the same way: one plan, many real houses.

    Big idea

    The three compartments of a class

    Every class is drawn as a rectangle split into three parts, from top to bottom: its name, its attributes (what it knows), and its operations (what it can do). Click each part of the box to explore it.

    Idea 2.1 · Name, attributes, operations
    BankAccount
    - owner : String
    - balance : double
    - iban : String
    + deposit(amount : double) : void
    + withdraw(amount : double) : boolean
    + getBalance() : double
    Idea 2.2 · From words to a class

    How to find classes, attributes and operations

    • Nouns in a description often become classes: "A student enrolls in a course."
    • Properties of a noun become attributes: a student's name, id.
    • Verbs become operations: enroll, pay, print.
    • Class names are singular and Capitalized: Student, not students.
    Analogy · An ID card

    Think of a class as an ID card template. The title says what kind of card it is. The middle lists the facts printed on it (name, birth date). The back lists what the holder is allowed to do (enter the library, borrow books).

      Big idea
      
    
      Visibility: who may see what
      
    
      The small symbol in front of each attribute or operation says which other classes are allowed to use it. Hiding the inside of a class and offering a few public operations is called encapsulation.
      

    
      
      Idea 3.1 · Four symbols
      
      
        
      +
      publicAny class can use it.
      
        
      -
      privateOnly the class itself.
      
        
      #
      protectedThe class and its subclasses.
      
        
      ~
      packageClasses in the same package.
      
      
      
    
      

    
      
      Idea 3.2 · The house analogy
      
      
        
      
          
      Analogy · Rooms of a house
      
          
      The living room is public: guests walk in. Your bedroom is private: only you. The family kitchen is protected: you and your children. The street mailbox is package-level: the neighbors on your street can reach it.
      
        
      
        
      
          
      Rule of thumb for beginners
      
          
        
            
      • Make attributes - private.
        • 
            
      • Make the operations other classes need + public.
        • 
            
      • Use # only when a subclass truly needs the member.
        • 
            
      • Programming languages differ in details. In Java, for example, protected members are also visible inside the package.
        •

      Big idea
      
    
      Writing attributes and operations
      
    
      UML has a small grammar for each line in a class. The type always comes after a colon, which is the opposite of Java or C. Learn these two patterns and you can read almost any class.
      

    
      
      Idea 4.1 · Two patterns
      
      
        
      
          
      Attribute
      
          
      visibility name : Type [multiplicity] = default
      
          
      Operation
      
          
      visibility name(param : Type, …) : ReturnType
      
          
        
            
      • Underlined means static: it belongs to the class, shared by all objects.
        • 
            
      • Italic means abstract: declared here, implemented by subclasses.
        • 
            
      • Parts in brackets are optional. Beginners can often leave them out.
        • 
          
      
        
      
        
      
          
      Analogy · A delivery label
      
          
      An operation line is like a delivery label. The symbol says who may send it, the name says what it is, the brackets list what you must hand over, and the part after the last colon says what you get back.
      
        
      
      
      

      
      
        
      Simulation

    05
    
      Big idea
      
    
      Associations and multiplicity
      
    
      An association is a solid line between two classes. It means their objects are linked and know about each other: a Teacher teaches a Course. Numbers on the line, called multiplicity, say how many objects can be linked.
      

    
      
      Idea 5.1 · Reading the numbers
      
      
        
      1exactly one
      
        
      0..1zero or one
      
        
      *any number (0..*)
      
        
      1..*one or more
      
        
      2..4between two and four
      
      
      
      
      
        
      
          
      Read the number at the far end
      
          
      In Person 1 ── 0..1 Passport, start at Person and walk along the line. The number you find next to Passport (0..1) tells you how many passports one person can have. Walk back the other way: each passport belongs to exactly 1 person.
      
          
      You can also add a name to the line (owns), role names at each end, and an open arrowhead to show which side can navigate to the other.
      
        
      
        
      
          
      Analogy · Seats and tickets
      
          
      A concert ticket gives you exactly 1 seat, and a seat can be sold to 0..1 ticket. Multiplicity is the rule printed on the box office wall: break it and the system is in an invalid state.

      uml / 06-aggregation-vs-compositionWindow 6 of 11
      
  
      
    06
    
      Big idea
      
    
      Whole and parts: aggregation vs composition
      
    
      Some associations mean "is made of" or "has". UML adds a diamond on the side of the whole. The diamond's color answers one question: when the whole is destroyed, do the parts die too?
      

    
      
      Idea 6.1 · White or black diamond
      
      
        
      
          
      Aggregation · A team and its players
      
          
      A white (hollow) diamond ◆ means a weak "has-a". Parts can exist on their own and can be shared. If a team is disbanded, the players are still people and can join another team.
      
        
      
        
      
          
      Composition · A house and its rooms
      
          
      A black (filled) diamond ◆ means a strong "made of". Each part belongs to exactly one whole, and lives and dies with it. Demolish the house and its rooms are gone.
      
        
      
      
      

      
      
        
      Simulation
      The demolition test
      Delete the whole and see what happens to its parts.
      
        
      
          
      
            
      Aggregation ◆ Team has Players
      
            
      
            
      Three player objects are linked to one team object.
      
            
          
      
          
      
            
      Composition ◆ House is made of Rooms
      
            
      
            
      Three room objects belong to one house object.
      
            
          
      
        
      
        
      Tip: the diamond is always drawn touching the whole, never the part.

    07
    
      Big idea
      
    
      Inheritance: the "is-a" relationship
      
    
      When one class is a special kind of another, UML draws a generalization: a solid line with a hollow triangle pointing to the general class (the parent, or superclass). The child (subclass) automatically gets the parent's attributes and operations, and can add its own or change how an operation works (override).
      

    
      
      Idea 7.1 · The is-a test and abstract classes
      
      
        
      
          
        
            
      • Test with a sentence: "A Dog is an Animal" sounds right, so inheritance fits. "A Car is an Engine" sounds wrong: that is a "has-a".
        • 
            
      • The triangle always points up to the parent.
        • 
            
      • An abstract class is written with its name in italics (or with {abstract}). You cannot create objects of it directly.
        • 
            
      • An italic operation is abstract: each subclass must provide it.
        • 
          
      
        
      
        
      
          
      Analogy · A family recipe book
      
          
      Every child in a family gets grandma's recipe book (inherited members). Each child can add new recipes (own members) and can rewrite one recipe in their own style (override). The book still says "family recipe", so anyone asking for one gets a valid answer.

    08
    
      Big idea
      
    
      Interfaces, realization and dependency
      
    
      An interface is a contract: a list of operations with no code behind them. A class that promises to provide those operations realizes (implements) the interface, drawn as a dashed line with a hollow triangle. A dependency is the weakest link: a dashed line with an open arrow, meaning "uses for a moment".
      

    
      
      Idea 8.1 · The interface as a contract
      
      
        
      
          
      Analogy · A wall socket
      
          
      The socket does not care whether you plug in a phone, a laptop or an electric car. It only cares that the device has the right plug. The socket is the interface; every device with that plug realizes it.
      
        
      
        
      
          
        
            
      • Draw an interface as a class box with «interface» above the name.
        • 
            
      • It usually has only operations.
        • 
            
      • Many unrelated classes can realize the same interface.
        • 
          
      
        
      
      
      
      
      
        
      Simulation
      Plug it in
      Tap a device. Only classes that realize Chargeable will charge.
      
        
      
          
      
          
      
          
      
          
      
        
      
      
      
    
      

    
      
      Idea 8.2 · Dependency: using without keeping
      
      
        
      
          
      If a class only uses another class briefly (as a parameter, a local variable, or by calling a static method) and does not keep a reference in an attribute, that is a dependency. A change in the used class might break the user, which is why we still draw it.
      
        
      
        
      
          
      Analogy · A borrowed knife
      
          
      A chef borrows a knife only while cooking, then gives it back. No long-term relationship, but if the knife were blunt, cooking would fail.
